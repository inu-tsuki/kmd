## 1. 完成定义（并行建造版）

旧文「行为中立」要求作废：B0.1 不喂旧 runtime，无需对旧行为中立；旧前端冻结不改，继续服务编辑器。
B0.1 完成时，下列事实同时成立：

1. `ChainParser` 在自己的模块空间（`packages/core/src/parser/chainSyntax/`）全量产出
   canonical §2.3 节点家族：主语、拍、连接符（含贝塞尔四数缓动）、从句、引用定界、量词类型化（D24）。
2. `@` 行四句类（canonical §2.2）在 root 完成**分类**：`Predicate` 全量解析；
   `Definition / Assignment / MemberOp` 识别 kind + 左部结构 + 右部保 slice，结构化实现留给各自切片（B0.4/B1）。
3. 引用**定界**完成（canonical §2.5.4）：`$name` 与 `$(...)` 的平衡括号边界正确，
   内部表达式保 slice，B0.4 再结构化。
4. 结构化诊断：每个诊断携带 `{ code, severity, message, range }`；错误恢复产 ErrorNode + diagnostic，
   不整链报废（B6 再完善 doesNotUnderstand 建议）。
5. 自建证据库：新语法 fixture 语料 + chain syntax golden（树形 / range / 诊断快照）全绿；
   设计探针脚本（canonical §7.1）能在新前端解析。
6. **零接触旧前端**：不 import 旧 parser 类型、不接任何生产入口、不改旧前端任何文件；
   旧门禁全绿是「没碰它」的自然结果，不是兼容证明。
7. reader-runtime 边界照旧：新模块属 `packages/core`，不 import Vue/Pinia/Monaco/TextMate/Pixi/editor panels，
   `pnpm core:check` 守护。

**明确不承诺**：旧语料零 diff、旧 coercion 复刻、旧 corpus 的 compat view——这些概念在本交付模型下不存在。

## 2. 输入契约

```text
ChainParser.parse(slice: string, baseOffset: number)
  → { expression: ChainExpressionAst, diagnostics: Diagnostic[] }
```

- **slice** = `@` 右侧完整表达式（不预先按空白拆链）；**baseOffset** = slice 在**未 trim 原始行**中的绝对列偏移。
  所有节点 range 以原始行坐标系表达（`raw === line.slice(range.start, range.end)` 对未 trim 行成立）。
- 目标态供方是 DocumentParser（`@` 行、`[...]` 段首句子槽）；**建造期只有 fixture 供方**。
  入口接线属切换日（canonical §7），B0.1 不做。
- **LiteralParser 是共享模块**：链参数与正文 inline pause `|(...)` 的字面量语言只有一个实现
  （D24/D27 同一字面量家族）。B0.1 建 LiteralParser；ContentScanner（B2 骨架，canonical §2.4）届时复用它，
  不允许第二条 `parseParams` 降级路径。
- **不属于链语法**：frontmatter 与 block-option `key=value` 是独立 scalar 配置面，归 frontmatter-schema
  （D22 展开文档）管；B0.1 不解析、不迁移它们。

## 3. 词法约定

```ebnf
IDENT       = IDENT_START, { IDENT_CONTINUE } ;
IDENT_START = ASCII_LETTER | "_" | non_ascii_letter ;
IDENT_CONTINUE = IDENT_START | DIGIT | "-" ;

SIGN        = "+" | "-" ;
INTEGER     = DIGIT, { DIGIT } ;
FRACTION    = ".", DIGIT, { DIGIT } ;
EXPONENT    = ( "e" | "E" ), [ SIGN ], INTEGER ;
NUMBER      = [ SIGN ], ( INTEGER, [ FRACTION ] | FRACTION ), [ EXPONENT ] ;

STRING      = '"', { escaped_char | not_quote }, '"'
            | "'", { escaped_char | not_apostrophe }, "'" ;

BOOLEAN     = "true" | "false" ;
```

说明（吸收自候选设计，compat 注记已删）：

- command 名中的 `.` 不属于 `IDENT`，由链结构消费。
- `+` / `-` 按位置与最长匹配裁决：member 起点 = 成员操作符（D6）；number 起点 = 正负号；`+=`/`-=` = 相对量词。
- 字符串内的 `, . ( ) ! ~ > = @` 不参与外层语法；escape 序列保留进 `raw`，`value` 存解码结果。
- **词法是语境敏感的，不做独立 tokenizer**（canonical §2.4）：`~` 在正文是 slow 糖、在参数是值域、
  在拍间是连接符；`.` 在链头是裸主语引导、在链身是成员分隔、在 `.(...)` 是从句引导。
  由当前产生式决定如何读下一字符（scannerless cursor）。
- 注释与顶层 `@` 边界由文档/段落层（目标态 DocumentParser）处理，链 parser 不重复扫描注释；
  前提是外层 scanner 必须 quote-aware、escape-aware、depth-aware——字符串中的 `//` 与 `@` 不截断。

## 4. 句子与成员文法（目标态）

```ebnf
chain-expression  = sentence, { sentence-separator, sentence } ;
sentence          = subject, ".", predicate            (* 显式主语句 *)
                  | predicate ;                        (* 隐式主语：裸点句 *)
subject           = selector | IDENT ;
selector          = "{", [ selector-content ], "}" ;   (* 顺序/内容选择器语义归 B0.2 *)
predicate         = beat, { connector, beat } ;
beat              = member, { ".", member } ;
member            = command-member | subclause | reference ;

command-member    = [ member-op ], IDENT,
                    [ granularity ], [ argument-list ], [ "!" ] ;
member-op         = "+" | "-" ;                        (* D6 成员操作；语义归 B0.4 *)
granularity       = ":", ( "char" | "group" | "block" ) ;
argument-list     = "(", [ argument, { ",", argument } ], ")" ;
argument          = IDENT, "=", value                  (* 命名参数 *)
                  | value ;                            (* 位置参数 *)

subclause         = ".", "(", sentence, ")", [ granularity ], [ "!" ] ;   (* D10 规范形 .(...) *)
reference         = "$", ( IDENT | "(", expression-slice, ")" ) ;

connector         = hold-connector | ease-connector ;
hold-connector    = "-", time-quantity, "->" ;
ease-connector    = "~", time-quantity, [ ",", curve ], "~>" ;
curve             = IDENT                              (* 命名预设 *)
                  | NUMBER, ",", NUMBER, ",", NUMBER, ",", NUMBER ;       (* 贝塞尔四数，canonical §2.5.1 *)

sentence-separator = top-level-whitespace ;            (* B0 只实现空白分隔 *)
```

与候选设计的两处**有意分歧**：

- **从句形态**：候选 EBNF 写 `subclause = "(", sentence, ")"`；规范形是 D10 的 `.(句子)`——
  拍起点的裸 `(` 不是从句引导（歧义裁决 2）。
- **无 legacy element union**：候选设计有 `legacy-command-chain` 根元素与 `compatSourceForm` provenance；
  目标态一切链皆句子——旧 `left(1self)` / `goto(p).rainbow` 形态由隐式主语句子自然覆盖（歧义裁决 1），
  不需要过渡形状。`f.` 前缀无特判（D5 废除）：`f` 只是普通 IDENT 主语，B0.2 作用域查找裁决其命运。

**歧义裁决表**：

1. **主语判定（纯形状）**：元素以「不带参数、粒度、阻塞符、操作符的纯 `IDENT` 后接 `.`」开头 → 显式主语句
   （`cam.zoom(1)`、`red.bold` 的 `red`、`upobj.wave`）；否则为隐式主语句子，首个 member 从该 token 起
   （`left(1self)`、`goto(p).rainbow`、`.wave`）。主语是用户对象、内建主语还是注册表名字，是 B0.2 的语义问题；
   parser 不持有任何内建主语名单。
2. 参数括号只能紧跟 command member；beat 起点裸 `(` = 诊断（非从句、非成员）。
3. `~>` 在参数括号内 = range 量词；拍之间 = 连接符（语境区分，canonical §2.5.2 结案）。
4. `$(...)` 的平衡括号属于 reference（quote/escape/depth-aware balanced read）；内部首轮保 slice。
5. connector 前后空白是 trivia；顶层空白 = 句子分隔符（separator kind `slot`）。
   `+` 在句子间可识别为 separator kind `parallel`，产诊断 `chain-parallel-not-enabled`
   （重开实例 1 缓发；AST 保留结构位，不实现并联语义）。
6. **解析必须消费整个输入**——substring match 与尾随垃圾静默成功均不允许（尾随垃圾 → `chain-unexpected-token`）。
7. `:bg` 不是粒度：产 `chain-invalid-granularity`（债 #9 根除；`bg` 是主语，重开实例 3，canonical §2.3）。

## 5. 句类分类（root 契约，canonical §2.2 落地）

分类是纯语法判定（有无 `=`、左部形态、`+/-` 前缀），在 root 一次完成：

| 判定 | kind | B0.1 产物 |
| --- | --- | --- |
| 无 `=`，无成员操作符 | `Predicate` | 全量句子树 |
| `IDENT = 链`（左部裸名） | `Definition` | kind + 左部 name + 右部 chain slice | 
| `path = 表达式`（左部含 `var.` 前缀或点路径） | `Assignment` | kind + 左部 path + 右部 expr slice |
| 主语后首个 member 带 `+`/`-` 操作符 | `MemberOp` | kind + 句子树（op 已在 member 上） |

- `Definition` 与 `Assignment` 的分流依据 D19：裸名 = 场景级定义，`var.` = 文档级状态。
  这条分流是**语法可判定的**（前缀检查），不涉及作用域查找。
- `MemberOp` 的句子按普通句子解析（op 是 `CommandMember.op` 字段），语义（对象成员操作）归 B0.4。
- 右部 slice 保 `raw + range`（平衡读取），结构化推迟不是丢失：B0.4/B1 在自己的切片里从 slice 结构化，
  输入契约与 ChainParser 相同。

## 6. AST 节点形状

canonical §2.3 家族的施工级定义（`SyntaxNodeBase` 公共约束 + 各节点）。**无任何 legacy 字段**：
没有 `compatSourceForm`、`legacyCoercion`、`sourceForm`、过渡 union。

```ts
interface SyntaxNodeBase {
  raw: string;            // 源面貌：raw === line.slice(range.start, range.end)
  range: SourceRange;     // [start, end)，相对未 trim 原始行（baseOffset 已折入）
}

interface ChainExpressionAst extends SyntaxNodeBase {
  type: 'chain-expression';
  sentences: SentenceAst[];
  separators: SentenceSeparatorAst[];   // kind: 'slot' | 'parallel'（parallel 伴诊断）
}                                       // 不变量：sentences.length === separators.length + 1

interface SentenceAst extends SyntaxNodeBase {
  type: 'sentence';
  kind: 'predicate' | 'definition' | 'assignment' | 'member-op';
  subject: SubjectAst | null;           // null = 隐式主语（裸点句）
  beats: BeatAst[];                     // Predicate/MemberOp 全量；Definition/Assignment 右部为 slice
  payload?: { name?: IdentifierAst; path?: IdentifierAst[]; slice?: ExpressionSliceAst };
}

type SubjectAst = SelectorSubjectAst | IdentifierSubjectAst;
// SelectorSubjectAst：'{' [content] '}'——顺序/内容语义归 B0.2
// IdentifierSubjectAst：纯 IDENT——内建/用户/注册表身份归 B0.2

interface BeatAst extends SyntaxNodeBase {
  type: 'beat';
  connectorBefore: ConnectorAst | null; // 首拍为 null
  members: MemberAst[];
}

interface ConnectorAst extends SyntaxNodeBase {
  type: 'connector';
  kind: 'hold' | 'ease';
  duration: TimeQuantityAst;
  easing: EasingAst | null;             // ease 必有；hold 必无
}

type EasingAst = NamedEasingAst | BezierEasingAst;   // §2.5.1：预设名 | 四数直连（x∈[0,1] 越界诊断）

type MemberAst = CommandMemberAst | ClauseMemberAst | ReferenceMemberAst;

interface CommandMemberAst extends SyntaxNodeBase {
  type: 'command-member';
  op: '+' | '-' | null;                 // D6 成员操作；B0.4 语义
  name: IdentifierAst;
  granularity: GranularityAst | null;   // unit ∈ char|group|block——不含 bg
  args: ArgAst[];
  blocking: boolean;                    // '!'
}

interface ClauseMemberAst extends SyntaxNodeBase {
  type: 'clause-member';
  sentence: SentenceAst;                // 递归
  granularity: GranularityAst | null;
  blocking: boolean;
}

interface ReferenceMemberAst extends SyntaxNodeBase {
  type: 'reference-member';
  form: 'name' | 'expr';
  delimited: string;                    // 定界产物；expr 内部结构化归 B0.4
}

interface ArgAst extends SyntaxNodeBase {
  type: 'arg';
  name: IdentifierAst | null;           // 命名参数
  value: ValueAst;
}

type ValueAst = LiteralAst | NameRefAst | ExpressionSliceAst;
// NameRefAst { path: IdentifierAst[] }——'p' / 'var.delay' / 'a.b'；绑定归 B0.2/B1
// ExpressionSliceAst { delimited }——非字面量非名字的参数值保平衡 slice；结构化归 B1 求值器
```

**对 canonical §2.3 的一处细化（本文档定案）**：canonical 的 `ArgAst.value: LiteralAst` 收窄了——
参数值还有名字引用（`goto(p)`、`shake(strength=var.x)`）与复杂表达式两类，语法层必须表达为
`NameRef` 与 `ExpressionSlice`，否则 B0.2/B1 无结构可绑定。这与 canonical「语法层不越权做语义决定」
完全同向：只保结构，绑定与求值在后。

**量词判别联合**（LiteralAst 的类型化成员，D24）：

```ts
type LiteralAst =
  | NumberLiteralAst                    // { value: number }——无 provenance 字段
  | StringLiteralAst                    // { value: string(解码后), quote: '"' | "'" }
  | BoolLiteralAst
  | TimeQuantityAst                     // { value, unit: 's' | 'ms' }
  | SpaceQuantityAst                    // { value, unit: 'char' | 'line' | 'self' | 'px' }
  | AngleQuantityAst                    // { value, unit: 'deg' }
  | RateQuantityAst                     // { value, numeratorUnit?: 'deg', denominatorUnit: 空间单位 }
  | RelativeQuantityAst                 // { operator: '+=' | '-=', value: number }
  | RangeLiteralAst                     // { from: RangeEndpoint, duration?: TimeQuantityAst, to: RangeEndpoint }
  | EventLiteralAst;                    // { event: 'click' }——signal:name 留 Phase C

type RangeEndpoint = NumberLiteralAst | TimeQuantityAst | SpaceQuantityAst
                   | RelativeQuantityAst | NameRefAst | ExpressionSliceAst;
// 'var.a~>var.b' 与表达式值域不被字符级 AST 堵死（吸收自候选设计）
```

**range/raw 不变量**（吸收自候选设计 §3.1）：

- 每个非合成节点 `raw === line.slice(range.start, range.end)`；
- parent range 包含所有 child range；siblings 不重叠；分隔符归 parent 所有；
- 数值节点保存解析值与 raw，不用浮点值反推源码；
- 诊断 range 指向最小出错切片；EOF 错误允许零宽 range；
- AST 不携带 family——syntax parser 不查注册表、不 import runtime manager（canonical 附录 A 纪律）。

## 7. 字面量语言细则

**字符串**：双引号 / 单引号；`value` = 解码后的语义值，`raw` = 含引号原文。
**有意变更（明文）**：目标语义直接消费 decoded value。旧 parser「只去引号、不解 escape」的行为
随旧前端死亡，不复刻——含 escape 的字符串在新语料中按解码义解释。

**数字**：`+1`、`.5`、`-.5`、`1e3`、`1E-2` 均为规范合法 NUMBER（词法比旧 `autoConvert` 的 decimal
regex 更宽是**有意的**）。value = 解析数值；无 legacy projection 分支，无 raw-string 降级形态。

**量词**：

| 族 | 单位 | 备注 |
| --- | --- | --- |
| 时间 | `s` `ms` | 语义层折秒；语法层保原单位 |
| 空间 | `char` `line` `self` `px` | |
| 角度 | `deg` | |
| 速率 | `[deg] / 空间单位` | `15deg/char`、`0.98/char`；执行归 B0.3/flow |
| 相对 | `+=` `-=` | 裸 `+0.1` 恒为正数字面量（canonical §2.5.5） |
| 值域 | `a~>b` / `a~d~>b` | 成员局部 tween 语义归 B0.3 |
| 事件 | `click` | 裸 `click` 关键词 = 事件量词；与同名 mark 的撞名归 B0.2 诊断面 |

- **负量词**：词法接受 `-1s`、`-0.5line`；某命令是否允许负值属 commandCatalog metadata / 语义验证，
  词法不静默拒绝（吸收自候选设计）。
- **默认单位**：语法层不补——裸 `Number` 进 IR 前由 SemanticLowerer 查 commandCatalog metadata 补全
  （canonical §5.3 已定）。
- **malformed 收紧（有意变更）**：`1ss`、`1mss`、`ms`、`1/`、`~>1`、`1~x~>2` 等形似而残缺的输入
  产 `chain-invalid-quantity` + invalid-value recovery node。旧 parser `parseFloat + substring` 的偶然容忍
  （`1ss → 1`）明文收紧，不复刻。测试名须标注 intentional tightening。

## 8. 解析器工艺

**Cursor**（scannerless，线性复杂度，禁止 substring + regex 回溯的二次复杂度）：

- `peek(offset)` / `consume()` / `consumeIf(text)`；
- `mark()` / `rangeFrom(mark)`；
- `skipInlineWhitespace()`；
- quote-aware、escape-aware、depth-aware 的 `readBalanced()`（`$(...)`、表达式 slice、字符串共用）；
- `expect(text, code)`：失败产 diagnostic，不抛到全局 catch。

**参数解析深度规则**：逗号只在当前参数 depth 0 且不在字符串中时分隔；命名参数的 `=` 只在 value depth 0
时生效。下列输入必须结构完整（吸收自候选设计）：

```kmd
effect(a=fn(1, nested(2, 3)), label="a,b")
$(var.enabled ? shake(strength=2) : wave)
.(cam.zoom(0.7~2s~>1.0))!
```

`fn(...)` 与复杂表达式首轮不求值：进 `ExpressionSliceAst`，但括号与 source range 必须正确。

**错误恢复（占位，B6 完善）**：出错产 ErrorNode + diagnostic，跳到恢复边界继续，不整链报废；
parser 返回 `{ ast, diagnostics }`，不以异常表示作者输入错误（编程错误才允许抛出）。

| 错误 | 恢复边界 |
| --- | --- |
| 未闭合字符串 / 参数 / 从句 / `$()` | 当前 sentence 末尾；保留此前完整成员 |
| 连续 `..`、connector 后无 beat | 下一个合法 member 起点或句子分隔符 |
| 非法粒度（含 `:bg`） | 跳过到 `(`、`!`、`.`、connector 或 sentence 末尾 |
| 参数尾随逗号 / 缺值 | 下一个逗号或右括号 |
| 非法量词 | 保留 invalid-value recovery node |
| 尾随垃圾 | `chain-unexpected-token`，不得静默成功 |

## 9. 结构化诊断

**B0.1 只产语法诊断。**语义诊断（D17 失配、D21 重名/shadowing、D18 弃用形态、unknown-command
的作用域版本）归 B0.2+；`doesNotUnderstand` 建议归 B6。

稳定 code 表（吸收自候选设计，compat 项已删）：

| code | 条件 | severity |
| --- | --- | --- |
| `chain-unclosed-argument-list` | `(` 未闭合 | error |
| `chain-unclosed-subclause` | `.(...)` 未闭合 | error |
| `chain-unclosed-reference` | `$(` 未闭合 | error |
| `chain-unclosed-string` | 字符串未闭合 | error |
| `chain-empty-member` | `..` 或 beat 无 member | error |
| `chain-missing-beat` | connector 后无 beat | error |
| `chain-invalid-granularity` | 未知 `:suffix`（含 `:bg`） | error |
| `chain-invalid-quantity` | 形似量词而残缺 | error |
| `chain-invalid-argument` | 参数缺 key/value 或尾逗号 | error |
| `chain-unexpected-token` | 完整解析后仍有尾随输入 | error |
| `chain-easing-out-of-range` | 贝塞尔 x ∉ [0,1]（canonical §2.5.1） | error |
| `chain-parallel-not-enabled` | 句间 `+`（重开实例 1 缓发） | warning |

诊断形状 `{ code, severity, message, range }` 是新前端的唯一诊断合同——B0.2 起的语义诊断、
LSP 未来接入（PR #29「记录不修」项的归宿：结构化 code/range 直达，不再反解析消息文本）都长在这个形状上。

## 10. 证据与验收

**建造期验收**（canonical §7.3 的 B0.1 实例化）：

1. **fixture 语料**（自建，不借旧 corpus）：
   - member 维度：1/3+ 成员、粒度、阻塞符、命名/位置参数、完整消费；
   - 嵌套维度：嵌套调用、嵌套从句、`$()`、括号内逗号/等号/点不误切；
   - 字符串：单/双引号、escape、字符串内全分隔符；
   - 分隔与连接符：slot separator、connector 周围 trivia、hold/ease、贝塞尔四数与命名预设、
     range 与 `sentences = separators + 1`；
   - 引用 / 从句：定界形状、`.(...)!` 外置阻塞、`+` 缓发诊断；
   - 句类：四 kind 分类矩阵（含 `var.` 前缀分流、MemberOp op 前缀）；
   - source range：每节点 raw/slice 相等、parent/child 包含、siblings 不重叠；
   - 恢复：每个稳定 code 一个聚焦用例；错误后独立句子仍可解析。
2. **量词参数化矩阵**：time / space / angle / rate / relative / range（含 `var.a~>var.b`）/ event
   各族合法形 + near-miss（`1ss`、`ms`、`1/`、`~>1`、`1~x~>2`）必须诊断、不静默截断。
3. **chain syntax golden**：树形 + range + 诊断快照；`pnpm test:golden:write` 再生后人工审 diff 纪律不变。
4. **设计探针**：用目标语法新写脚本压解析器（canonical §7.1「接触现实不等切换日」）。
5. **冻结纪律**：PR diff 审计——旧前端文件零改动；`pnpm build / test / test:parser / core:check`
   全绿（旧套件绿 = 没碰它）。

## 12. 边界与非目标

B0.1 明确不做（消费 B0.1 AST 是后续切片的义务，不得重扫 raw string）：

- receiver 作用域查找（场景级 → 文档级 → 内建 → 注册表，canonical §3.1）；
- `{}` 顺序选择器与 `{文本}` 内容选择器语义；D17 失配、D18 弃用、D21 重名诊断；
- 点/域类型与 `.line/.start/.end/range` 访问器（D14）；
- `bg` 主语语义、`$()` 求值与展开、`Definition/Assignment/MemberOp` 右部结构化；
- 控制流结构行（`#` / `->` / `[...]` / `---` 归 DocumentParser，B2）；
- **任何与旧前端的接线、任何 legacy 投影、任何 compat golden**。
