## 1. 完成定义

B0.1 完成时，下列事实必须同时成立：

- `KMDCommandParser` 中的 `NAMESPACE_CAM_DOT_` 和成员正则已删除；
- 链成员、参数、嵌套括号、从句、`$()`、值域和连接符由同一个递归下降前端结构化；
- 时间/空间/角度/速率/相对/值域/事件 quantity 在 syntax AST 中有类型、有单位、有 raw、有 range；
- 已实现的旧语法只经一个 `LegacyCommandAdapter` 把 typed value 降为 legacy command value；现有 `CompatProjector` 只负责后续 ParagraphIR → runtime-shaped data；
- 旧 corpus 的 compatibility view、ParagraphIR、tokens、effects、layout instructions 和 runtime 行为零变化；
- 未到 B0.2–B0.4 的新语义只能在 syntax AST 与 diagnostics 中观察，不进入 runtime；
- `parseInstruction()` 不再静默取链首：无调用点则删除，有兼容需要则返回完整 projected chain 或显式拒绝多成员；
- top-level command、block-option command 与 inline `|(...)` 的 value 均已接到同一个 frontend/literal/adapter 合同，段落层 comment 与 range 处理不截断引号内源码；
- parser/LSP diagnostics 走结构化统一入口，command-only/无 runtime payload 的诊断不丢失，source range 不退化；
- `KMDParagraphData.ast` 可以暴露 typed AST 给 transform/tooling，但 runtime 不从 typed value 反建参数；
- 新增 parser suite 已接入 `pnpm test:parser`，不会只在完整 `pnpm test` 中偶然运行。

“行为中立”指已实现脚本的可观察执行语义不变，不指内部 AST 必须保持旧的无类型形状。

## 2. 输入语法

### 2.1 词法约定

```ebnf
IDENT       = IDENT_START, { IDENT_CONTINUE } ;
IDENT_START = ASCII_LETTER | "_" | non_ascii_letter ;
IDENT_CONTINUE = IDENT_START | DIGIT | "-" ;

SIGN        = "+" | "-" ;
INTEGER     = DIGIT, { DIGIT } ;
FRACTION    = ".", DIGIT, { DIGIT } ;
EXPONENT    = ( "e" | "E" ), [ SIGN ], INTEGER ;
NUMBER      = [ SIGN ], ( INTEGER, [ FRACTION ] | FRACTION ), [ EXPONENT ] ;

STRING      = '"', { escaped_char | not_quote }, '"'
            | "'", { escaped_char | not_apostrophe }, "'" ;
```

说明：

- command 名中的 `.` 不属于 `IDENT`，由链结构消费；
- `+` / `-` 在 member 起点可为对象操作，在 number 起点可为正负号，在 `+=` / `-=` 中为相对操作，按当前位置和最长匹配裁决；
- 字符串内的 `, . ( ) ! ~ > =` 都不参与外层语法；escape 保留 raw，value 保存解码后的字符串；
- 字符串节点同时保存含引号的 `raw` 与解码后的 `value`；二者服务不同编译阶段，不允许用 decoded value 反推 compatibility string；
- 注释与顶层 `@` 由段落 parser 处理，链 parser 不再次扫描注释；前提是段落 parser 的 scanner 必须 quote-aware、escape-aware、depth-aware，不能先截断字符串中的 `//` 或 `@`。

### 2.2 链与成员 EBNF

```ebnf
chain-expression = chain-element,
                   { sentence-separator, chain-element } ;
chain-element    = sentence | legacy-command-chain ;

sentence          = subject, ".", predicate ;
subject           = IDENT | selector | legacy-subject ;
selector          = "{", [ selector-content ], "}" ;
legacy-subject    = "f" | implicit-subject ;
implicit-subject  = /* zero-width subject before leading dot */ ;
predicate         = beat, { connector, beat } ;
sentence-separator = top-level-whitespace | "+" ;

beat              = member, { ".", member } ;
member            = command-member | subclause | reference ;

command-member    = [ member-operation ], IDENT,
                    [ granularity | legacy-bg-suffix ],
                    [ argument-list ],
                    [ "!" ] ;

member-operation  = "+" | "-" ;
granularity       = ":", ( "char" | "group" | "block" ) ;
legacy-bg-suffix  = ":bg" ;

argument-list     = "(", [ argument, { ",", argument } ], ")" ;
argument          = named-argument | positional-argument ;
named-argument    = IDENT, "=", value ;
positional-argument = value ;

subclause         = "(", sentence, ")", [ granularity ], [ "!" ] ;
reference         = "$", ( IDENT | "(", expression-slice, ")" ) ;

connector         = hold-connector | ease-connector ;
hold-connector    = "-", time-quantity, "->" ;
ease-connector    = "~", time-quantity,
                    [ ",", IDENT ], "~>" ;

legacy-command-chain = legacy-command-member,
                       { ".", legacy-command-member } ;
legacy-command-member = command-member ;
```

`sentence` 是 Phase B 的耐久主谓形状：subject 只说明句法位置和源码形态；identifier 属于用户对象、内建主语还是未知名，由 B0.2 的作用域链决定。`legacy-f` 与零宽 `implicit-subject` 只保存兼容源码形态。

syntax parser 不查 registry，但可以按无歧义字符形状识别 subject：元素以不带参数、粒度、阻塞或操作符的纯 `IDENT` 后接 `.` 开头时产生 sentence。因此 `cam.zoom(1)`、`red.bold` 进入耐久 `SubjectSyntaxAst + ChainPredicateSyntaxAst`，同时在 sentence 上附 `compatSourceForm: 'legacy-bare-dot-chain'` 供 B0.1 适配旧行为。`goto(p).rainbow` 的首 member 带参数，不满足 subject delimiter；它与 `left(1self)` 进入可容纳一到多个 member 的 transitional `LegacyCommandChainSyntaxAst`。该兼容 element 不能成为保留旧正则的理由。

歧义裁决：

1. 参数括号只能紧跟 command member；beat 起点的 `(` 解析为 subclause；
2. 参数列表内的 `~>` 解析为 range quantity，参数列表外、beat 之间的 `~d~>` 解析为 connector；
3. `$(...)` 的括号属于 reference；内部首轮保存为 depth/quote-aware `expression-slice`，表达式语义留 B1/B0.4；
4. connector 前后的空白是 trivia；其余 top-level whitespace 产生 `slot` separator，`+` 产生 `parallel` separator；二者在 root 上显式可达，B0.1 不执行并联；
5. `cam.zoom` 不再靠字符串替换。sentence 保留 subject `cam` 与 predicate `zoom`，`LegacyCommandAdapter` 根据 sentence 的 compatibility provenance 在 B0.2 前按白名单历史规则折成 `cam.zoom` 命令名；`red.bold` 用同一 provenance 维持两个 legacy command；
6. 解析必须消费整个输入。正则的 substring match 或忽略尾随垃圾不被允许。

`:bg` 不属于 granularity。parser 只在兼容入口把它建模成 `LegacyCompatibilitySuffixAst`；规范 `GranularitySyntaxAst.unit` 始终限定为 `char | group | block`。

### 2.3 值与 quantity EBNF

```ebnf
value             = range-quantity
                  | relative-quantity
                  | rate-quantity
                  | unit-quantity
                  | event-quantity
                  | NUMBER
                  | STRING
                  | BOOLEAN
                  | identifier-value
                  | expression-slice ;

BOOLEAN           = "true" | "false" ;
identifier-value  = IDENT, { ".", IDENT } ;

time-quantity     = NUMBER, ( "ms" | "s" ) ;
space-quantity    = NUMBER, ( "char" | "line" | "self" | "px" ) ;
angle-quantity    = NUMBER, "deg" ;
unit-quantity     = time-quantity | space-quantity | angle-quantity ;

rate-quantity     = ( NUMBER, [ "deg" ] ), "/",
                    ( "char" | "line" | "self" | "px" ) ;

relative-quantity = ( "+=" | "-=" ), unsigned-number ;

range-quantity    = range-endpoint, "~>", range-endpoint
                  | range-endpoint, "~", time-quantity, "~>", range-endpoint ;
range-endpoint    = NUMBER
                  | unit-quantity
                  | relative-quantity
                  | identifier-value
                  | expression-slice ;

event-quantity    = "click" ;
unsigned-number   = ( INTEGER, [ FRACTION ] | FRACTION ), [ EXPONENT ] ;
```

B0.1 不扩展规范：`signal:name` 留 Phase C；相对 quantity 首轮只接受数字 payload；复杂表达式作为 `OpaqueExpressionAst` 保留原文，直到 B1 求值器接管。

单位 quantity 使用已含可选符号的 `NUMBER`，因此保留当前 `autoConvert()` 可接受的 `-1s`、`-0.5line` 等输入。规范尚未禁止负 quantity；具体 command 是否允许负值属于 metadata/semantic validation，不由 lexer 静默拒绝。range endpoint 允许 identifier 与 expression slice，确保 `var.a~>var.b` 和后续表达式值域不被字符级 AST 堵死。

词法识别与 B0.1 compatibility coercion 是两件事。新 grammar 有意比旧 `autoConvert()` 的 decimal regex 更宽，因此每个 number node 必须保存足以复刻旧值的 raw/provenance：

| raw | typed syntax | 当前 `autoConvert()` | B0.1 legacy projection |
| --- | --- | --- | --- |
| `1`, `-1`, `0.5`, `-0.5` | number | number | number |
| `+1`, `.5`, `-.5`, `1e3`, `1E-2` | number（规范合法） | string | 原始字符串 |
| `1s`, `-1s`, `500ms` | time quantity | seconds number | 同当前 seconds number |
| `+1s`, `.5s`, `1e3s`, `1e3ms`, `1E-2s`, `1E-2ms` | time quantity（规范 NUMBER 合法） | `parseFloat(raw)` 后按 suffix：`1`、`0.5`、`1000`、`1`、`0.01`、`0.00001` | 精确复刻当前 legacy value；typed value 同时保留 number/unit/raw 供 semantic branch |
| `1ss`, `1mss` 等 malformed/旧偶然 coercion | invalid quantity 或带明确恢复的 invalid value | 可能因 `parseFloat` + suffix 被偶然转 number | `chain-invalid-quantity`，不投影 runtime |

最后一行是明文的非法输入收紧：B0.1 的“行为中立”只承诺已实现的合法 corpus 与 runtime 语义；不承诺继续接受旧 parser 的 substring/`parseFloat` 偶然结果。任何其他合法输入变化仍须停下并由决策者标为有意变更。

## 3. 节点类型与 source range

### 3.1 公共节点约束

```ts
interface SyntaxNodeBase {
  raw: string;
  range: SourceRange; // [start, end), relative to source line
}

interface IdentifierSyntaxAst extends SyntaxNodeBase {
  type: 'identifier';
  name: string;
}

interface StringLiteralSyntaxAst extends SyntaxNodeBase {
  type: 'string';
  value: string; // decoded semantic value
  quote: '"' | "'";
}

interface NumberLiteralSyntaxAst extends SyntaxNodeBase {
  type: 'number';
  value: number;
  legacyCoercion: 'number' | 'raw-string';
}

interface LegacyCommandChainSyntaxAst extends SyntaxNodeBase {
  type: 'legacy-command-chain';
  sourceForm: 'bare';
  members: CommandMemberSyntaxAst[];
}

interface ChainSentenceSyntaxAst extends SyntaxNodeBase {
  type: 'chain-sentence';
  subject: SubjectSyntaxAst;
  predicate: ChainPredicateSyntaxAst;
  compatSourceForm?: 'legacy-bare-dot-chain';
}

type ChainExpressionElementSyntaxAst =
  | ChainSentenceSyntaxAst
  | LegacyCommandChainSyntaxAst;

interface ChainExpressionSyntaxAst extends SyntaxNodeBase {
  type: 'chain-expression';
  elements: ChainExpressionElementSyntaxAst[];
  separators: Array<
    | (SyntaxNodeBase & { type: 'chain-expression-separator'; kind: 'slot' })
    | (SyntaxNodeBase & { type: 'chain-expression-separator'; kind: 'parallel' })
  >;
}
```

- 每个非合成节点的 `raw === source.slice(range.start, range.end)`；
- parent range 包含所有 child range；siblings 不重叠，分隔符由 parent 或专门 connector 节点拥有；
- `elements.length === separators.length + 1`；separator 自带 raw/range 和 `slot | parallel` discriminant；
- parser diagnostics 的 range 指向最小出错切片；EOF 错误可用零宽 range；
- 数值节点同时保存解析值和 raw，不用浮点值反向生成源码；
- AST 不保存 effect/style/layout/stage family，避免 syntax parser 依赖运行时 registry。

### 3.2 Quantity discriminated union

```ts
type QuantityLiteralSyntaxAst =
  | TimeQuantitySyntaxAst
  | SpaceQuantitySyntaxAst
  | AngleQuantitySyntaxAst
  | RateQuantitySyntaxAst
  | RelativeQuantitySyntaxAst
  | RangeQuantitySyntaxAst
  | EventQuantitySyntaxAst;

interface TimeQuantitySyntaxAst extends SyntaxNodeBase {
  type: 'quantity';
  kind: 'time';
  value: number;
  unit: 's' | 'ms';
}

interface SpaceQuantitySyntaxAst extends SyntaxNodeBase {
  type: 'quantity';
  kind: 'space';
  value: number;
  unit: 'char' | 'line' | 'self' | 'px';
}

interface AngleQuantitySyntaxAst extends SyntaxNodeBase {
  type: 'quantity';
  kind: 'angle';
  value: number;
  unit: 'deg';
}

interface RateQuantitySyntaxAst extends SyntaxNodeBase {
  type: 'quantity';
  kind: 'rate';
  value: number;
  numeratorUnit?: 'deg';
  denominatorUnit: 'char' | 'line' | 'self' | 'px';
}

interface RelativeQuantitySyntaxAst extends SyntaxNodeBase {
  type: 'quantity';
  kind: 'relative';
  operator: '+=' | '-=';
  value: number;
}

interface RangeQuantitySyntaxAst extends SyntaxNodeBase {
  type: 'quantity';
  kind: 'range';
  from: RangeEndpointSyntaxAst;
  duration?: TimeQuantitySyntaxAst;
  to: RangeEndpointSyntaxAst;
}

interface EventQuantitySyntaxAst extends SyntaxNodeBase {
  type: 'quantity';
  kind: 'event';
  event: 'click';
}
```

`RangeEndpointSyntaxAst` 复用 number/unit/relative/identifier/opaque-expression 节点。range child 的 range 必须落在 parent range 内，便于编辑器精确标注某一端。identifier/expression 的值域语义等 B1 求值器接管，B0.1 只保结构。

## 4. Parser 算法与错误恢复

### 4.1 Cursor

实现一个局部 cursor，至少提供：

- `peek(offset)` / `consume()` / `consumeIf(text)`；
- `mark()` / `rangeFrom(mark)`；
- `skipInlineWhitespace()`；
- quote-aware、escape-aware、depth-aware 的 `readBalanced()`；
- `expect(text, code)`，失败产生 diagnostic 而非抛出到全局 parser catch。

整个链长度线性扫描；不得通过反复 substring + regex 回溯形成二次复杂度。

### 4.2 参数解析

`parseArgumentList()` 在同一 cursor 上递归解析 value。逗号只有在当前参数 depth 0 且不在字符串中时才分隔。命名参数的 `=` 也只有在当前 value depth 0 时生效。

因此下列输入必须保持完整结构：

```kmd
effect(a=fn(1, nested(2, 3)), label="a,b")
$(var.enabled ? shake(strength=2) : wave)
.(cam.zoom(0.7~2s~>1.0))!
```

首轮不会执行 `fn` 或表达式；它们进入 `OpaqueExpressionAst`，但括号和 source range 必须正确。

### 4.3 局部恢复

| 错误 | 恢复边界 |
| --- | --- |
| 未闭合字符串/参数/从句/`$()` | 当前 sentence 末尾；保留此前完整成员 |
| 连续 `..`、connector 后无 beat、空 `+` 分支 | 下一个合法 member 起点或 sentence separator |
| 非法 granularity | 跳过到 `(`、`!`、`.`、connector 或 sentence 末尾 |
| 参数尾随逗号/缺值 | 下一个逗号或右括号 |
| 非法 quantity | 保留为 invalid-value recovery node，不投影 runtime |
| 尾随垃圾 | 报 `chain-unexpected-token`，不得静默成功 |

syntax parser 返回 `{ ast, diagnostics }`，不以异常表示作者输入错误。真正的编程错误才允许抛出并由现有 `parser-failure` 兜底。

### 4.4 段落层接入合同

链 frontend 不拥有段落语法，但 S4 必须同时修好把 source slice 交给它的外层：

1. **top-level `@` command**：把 `@` 后完整 expression 与原始行 base offset 交给 root parser；不再先按空白拆 chain；
2. **block option**：外层 scanner 只在 quote/depth 0 识别 `key=value`。command 分支保存一个完整 typed root expression，不能继续把每个顶层空白分片包装为单一 `BlockOptionCommandAst.chain`；slot/parallel 仍由 root parser 记录；
3. **inline pause**：`|(...)` 使用 balanced reader 和同一个 `LiteralParser`，保留 raw/range。首轮只允许现有单参数合同；多参数或尾随垃圾给稳定诊断，不能回退裸逗号 split；
4. **comment 与 `@` scanner**：均须 quote/escape/depth-aware。字符串中的 `//`、`@` 和括号不改变段落边界；
5. **range**：所有 offset 相对未 trim 的 `originalLine`。block option 即使有前导缩进，child raw 仍满足 `sourceLine.slice(range.start, range.end)`。

block-option `key=value` 的 value 仍是旧 scalar 配置面，不在 B0.1 强行产生 typed chain literal；其 coercion 边界见 §5.2。

## 5. LegacyCommandAdapter 与现有 CompatProjector

### 5.1 单一投影规则

旧 runtime 仍消费 `ParsedCommand` / `EffectConfig.params`。B0.1 的 lowering 顺序为：

```text
typed ChainExpressionSyntaxAst
  -> LegacyCommandAdapter.adapt()
  -> attachCommandFamily(registry view)
  -> existing ScopeRouter
  -> ParagraphIR
  -> existing CompatProjector (tokens/globalEffects)
```

`LegacyCommandAdapter.adapt()` 是新 frontend 唯一的 typed value → legacy command value 降级点，输入 syntax AST，输出现有 `CommandChainAst/ParsedCommand` 兼容合同。它应位于独立模块，**不得**由现有 `CompatProjector.ts` 承载或调用。

adapter 还提供同源的 value 适配入口给 inline pause。`pause(click)` 的 command argument 与 `|(click)` 的正文参数都先由同一个 `LiteralParser` 建 typed value，再走同一 `adaptValue()` 规则；`parseInline()` 不得继续调用独立 `parseParams()`。这不意味着 inline pause 要伪装成 chain sentence，只表示 D24/D27 的 literal 与 legacy coercion 只有一个实现。

现有 `CompatProjector` 的合同保持不变：输入 `ParagraphAst + ParagraphIR`，输出 runtime-shaped `KMDParagraphData.tokens/globalEffects`。它只能复制已经适配完成的 legacy params，不解析 quantity、不读取 typed AST、不承担单位转换。完整顺序固定为 `syntax AST -> LegacyCommandAdapter -> ScopeRouter/lowering -> ParagraphIR -> CompatProjector -> runtime-shaped data`。

### 5.2 Quantity / scalar 兼容映射

| syntax value | typed AST | B0.1 legacy value | 原因 |
| --- | --- | --- | --- |
| `1` / `-0.5` | number | `1` / `-0.5` number | 保持当前数值 |
| `true` / `false` | boolean | boolean | 保持当前值 |
| `"text"` / `'text'` | decoded string + raw quote | `raw.slice(1, -1)` | 精确保持当前只去引号、不解码 escape 的行为；semantic branch 才用 decoded value |
| `+1` / `.5` / `1e3` | number + raw/provenance | 原始字符串 | 保持当前 decimal regex 不接受这些写法 |
| `var.delay` | identifier value | `"var.delay"` | 保持 RuntimeValueResolver 输入 |
| `1s` | time `{value:1,unit:'s'}` | `1` number | 当前 runtime 以秒为单位 |
| `500ms` | time `{value:500,unit:'ms'}` | `0.5` number | 保持当前 `autoConvert` 折秒行为 |
| `1e3s` / `1e3ms` / `1E-2s` / `1E-2ms` | time + raw/provenance | `1000` / `1` / `0.01` / `0.00001` number | legacy branch 精确复刻当前 `parseFloat` + suffix；semantic branch 读取同一规范 number/unit |
| `0.5line` / `1self` / `100px` | space | 原始字符串 | 现有 layout resolver 仍按字符串消费 |
| `15deg` | angle | 原始字符串 | 保持当前行为；语义消费后移 |
| `15deg/char` / `0.98/char` | rate | 原始字符串 | B0.3/flow 之前不执行 |
| `+=0.1` / `-=0.1` | relative | 原始字符串 | B0.1 不启用相对语义 |
| `a~>b` / `a~1s~>b` | range | 原始字符串 | B0.3 才启用成员局部 tween |
| `click` | event | `"click"` | B2/graph wait gate 前不执行事件时长 |
| 未识别裸值/复杂表达式 | identifier/opaque | 原始字符串 | 保持当前通用参数容忍面 |
| `1ss` 等 malformed quantity | invalid recovery node | 不投影 | 有意收紧旧 parser 的偶然 `parseFloat` 行为 |

映射只服务旧 runtime，不是 quantity 的规范语义。B1/B0.3 的 semantic lowerer 必须消费 typed node，不得再解析这些 legacy 字符串。

frontmatter 与 block-option `key=value` 不属于 chain syntax AST。当前 `autoConvert()` 的这两类使用方迁到独立、命名明确的 `legacyScalarCoercion`（实际文件名可等价）并保持旧行为；chain argument 和 inline pause 禁止调用它。`KMDCommandParser` 的 regex、独立 comma split 与 `parseInstruction()` 可以删除，但不能因非链使用方尚存而把旧 chain parser 整体留下。

### 5.3 历史链形态

| syntax 形态 | B0.1 投影 |
| --- | --- |
| `f.red.wave` | subject form `legacy-f`；投影 prefix `f`；commands `red`, `wave` |
| `.wave` | subject form `implicit-dot`；投影 prefix `dot`；command `wave` |
| `left(1self)` | prefix `bare`；command `left` |
| `goto(p).rainbow` | legacy element prefix `bare`；commands `goto`, `rainbow` |
| `cam.zoom(1).cam.move(2,3)` | prefix `bare`；折叠为 `cam.zoom`, `cam.move` |
| `:char/:group/:block` | 规范 granularity，投影为现有 `CommandLevel` |
| `:bg` | transitional legacy suffix，投影为现有 `CommandLevel.bg`；B0.2 偿还 |
| member `!` | 维持 `blocking` boolean |
| 新 connector/subclause/reference/parallel | 不投影；产生 `phase-b-feature-not-enabled` |

`cam` 折叠是明文的过渡规则，只在当前历史命名空间集合上执行；不得用任意 `a.b` 自动拼名，否则会堵死 B0.2 receiver 语义。

### 5.4 AST 与 golden 的兼容视图

当前 parser golden 包含 `ParagraphAst`、IR 和 legacy tokens。B0.1 会有意升级 command AST，不能把 typed node 强塞回旧 `commands[].params`，也不能因此盲目重写全部 golden。

采用两类证据：

1. **compatibility golden**：现有 serializer 对 command syntax 节点调用同一只读 `LegacyCommandAdapter`，输出与当前 `CommandChainAst.commands` 等价的视图；现有 golden 文件应零 diff；
2. **syntax AST tests/golden**：新增聚焦 suite，直接断言 typed member/value/quantity/range/source range 和 diagnostics，不经过 compat serializer。

serializer 的兼容视图只用于测试比较，不回流生产 parser，也不成为第二事实源。相关测试注释与 `test-net-design` 必须在编码包中同步，说明“完整 AST”已分成耐久 syntax 证据与 compatibility 证据。

## 6. Diagnostics

建议稳定 code：

| code | 条件 | severity |
| --- | --- | --- |
| `chain-unclosed-argument-list` | `(` 未闭合 | error |
| `chain-unclosed-subclause` | 从句未闭合 | error |
| `chain-unclosed-reference` | `$(` 未闭合 | error |
| `chain-unclosed-string` | 字符串未闭合 | error |
| `chain-empty-member` | `..` 或 beat 无 member | error |
| `chain-missing-beat` | connector 后无 beat | error |
| `chain-invalid-granularity` | 未知 `:suffix` | error |
| `chain-invalid-quantity` | 形似 quantity 但不完整 | error |
| `chain-invalid-argument` | 参数缺 key/value 或尾逗号 | error |
| `chain-unexpected-token` | 完整 parse 后仍有尾随输入 | error |
| `phase-b-feature-not-enabled` | syntax 合法但语义属于后续包 | warning |

`unknown-command` 继续由 registry adapter 产生。B0.1 不新增 selector mismatch、receiver lookup、跨 registry collision 或弃用诊断。

### 6.1 Parser/LSP 结构化合同

当前 `KMDParser.validate()` 只保留 `{ message, line }`，LSP 再按消息文本和源代码定位。这会丢失本节稳定 code 与最小 range，不能作为 B0.1 完成形态。S4 必须：

- 增加结构化 validation API，返回至少 `message/severity/code/line/range`；
- 保留旧 `validate()` façade，只从结构化结果投影 1-based `{ message, line }`；
- `packages/kmd-language-server` 直接消费结构化结果，不再用 unknown-command 正则、comment scanner 或整行 fallback 充当正常定位路径；
- parser 顶层先聚合 diagnostics，再独立决定是否生成 runtime paragraph。command-only、block-option-only、invalid/recovery 或未启用语法即使没有 token/globalEffect，也必须进入 `KMDParseResult.diagnostics`；
- LSP focused tests 同时覆盖精确 syntax range、unknown-command、quoted `//`、block-option 缩进和无 runtime payload 的错误。

### 6.2 Typed AST 暴露边界

`KMDParagraphData.ast` 在 B0.1 继续存在，供 `ParserAstTransform`、diagnostics、formatter/golden 与 source-line tooling 使用。下游限制：

- AST transform 可以读取或返回 typed syntax AST；
- lowering 只能把 typed root 交给 `LegacyCommandAdapter`，不得就地把 typed value 写进 `EffectParams`；
- `CompatProjector` 只能复制已适配的 IR；
- `SegmentBuilder` 等 runtime 为 seek/source anchor 读取 `line/kind/range` 是允许的，但不得读取 typed argument/value 并自行 coercion；
- compatibility serializer 只属于测试，不能被 production lowering 调用。

### 6.3 Gate 前 characterization 基线（2026-08-13）

在采纳方案 B 前，`apps/editor/src/test/parser-phase-b-characterization.test.ts` 只读冻结当前生产行为，不创建 typed AST 或 adapter：

- expected legacy：`+1/.5/1e3` 保持 string，`-0.5/1s` 当前为 number；指数 time 当前为 `1e3s → 1000`、`1e3ms → 1`、`1E-2s → 0.01`、`1E-2ms → 0.00001`；quoted string 只去引号、不解码 escape；
- known/current accidental gap：`1ss` 被偶然 coercion 为 `1`；nested/quoted comma 被 flat splitter 拆坏；quoted `//` 被截断；`|(click)` 仍走 legacy params；有缩进的 block option 被预拆且 range 丢列；command-only unknown diagnostic 随空 runtime paragraph 丢失；
- adoption target：`it.fails` 明示 `1ss` 后续应 intentional tightening、command-only diagnostic 后续应保留，不把尚未实现的目标伪装成当前绿行为。

该 suite 已明文接入当前 `pnpm test:parser`；2026-08-13 审计纠偏后的基线结果为 focused 18/18、完整 parser 门禁 85/85、`pnpm core:check` 通过。它是 gate 前证据，不代表 ADR 已被采纳；S1–S5 实施时按有意变化更新对应断言并人工审查 diff。

## 9. 风险与回滚

| 风险 | 预防/判定 | 回滚 |
| --- | --- | --- |
| typed object 泄漏到 effect/layout runtime | adapter boundary 类型检查 + runtime/golden tests | revert S4，不在 consumer 加临时 coercion |
| 新旧 parser 分叉 | 生产入口只有新 parser；旧类仅 façade | 删除 façade 或 revert 整体切换，不加 feature flag |
| `cam.*` 行为变化 | 专门 compat table + camera corpus | revert adapter fold 规则，B0.2 前不改语义 |
| nested input 被部分解析 | 全输入消费 + unexpected-token diagnostics | 修 parser；不得回退 substring regex |
| golden 大面积变化 | compatibility serializer + 零 diff gate | 停止，不运行 golden write 覆盖证据 |
| source range 偏移 | raw/slice property tests | revert生产切换，保留独立 parser 修正 |
| 未启用语法误执行 | `phase-b-feature-not-enabled` + no projection | 删除对应 projection，保留 AST |

仓库处于实验期，回滚依赖普通 Git revert，不新增 runtime feature flag、全局开关或持久化格式版本。`@kmd/core` 仍为 private，B0.1 不冻结公共 API。

## 10. B0.2 非目标清单

B0.1 明确不实现：

- receiver 的场景级 → 文档级 → built-in → command registry 查找；
- `{}` 顺序选择器和 `{文本}` 内容选择器；
- D17 链数/组数失配诊断与语料迁移；
- D18 裸排版链弃用；
- D21 shadowing/跨 registry 重名诊断；
- 点/域类型与 `.line/.start/.end/range`；
- `bg` 主语及 `CommandLevel.bg` 退役；
- `ScopeRouter` 的 first/last 行为改变。

这些项目必须消费 B0.1 的耐久 syntax AST，而不是重新扫描 raw string。
